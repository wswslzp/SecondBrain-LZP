# Diana Hu

[[y-combinator|Y Combinator]] General Partner。在 [[cs153-garry-tan-diana-hu-ai-native|CS153 "The AI Native Company" 讲座]]中，她接过 [[garry-tan|Garry Tan]] 的 code 层原语，讲**组织层（org level）如何变成 AI-native**——是 [[ai-native-company]] 概念页的主要来源。带有明显的 **control systems（控制系统）** 工程背景，用 open-loop / closed-loop、PID controller 来给公司建模。

## 核心论述

- **公司 = 一个控制回路**：旧公司是 **open loop**（信息散在人脑、Slack DM、没写的会议记录、vibes → 误差累积、脱轨）；AI 把它变成 **closed loop**——一个 agent 对**公司每个 artifact 有 read access**，主动建议下一步、self-heal。**YC 自己工程团队 sprint 减半、产出 10x。**
- **三种角色**：人人是**会 ship 的 IC**（连销售都自建 pipeline）；**DRI**（Directly Responsible Individual，Apple 术语）编排 IC 达成 outcome（常是 founder）；全新的 **AI founder**——活在边缘、试遍新工具、把创新带回公司。引 **Jack Dorsey 的 agentic organization**，主张更扁平、**更少中层**。
- **Taste & evals 不可外包**："shipping code 归零，taste 不归零。"通用 benchmark（MMLU）没用；要 human-in-the-loop 读 traces、标失败、转 evals、replay self-heal。捕获 trace 高度依赖产品形态（video vs speech vs B2B SaaS 各不同）。
- **GTM wedge**：选痛点 workflow，作为 **forward-deployed engineer** "go undercover" 去把那份工作干一遍学 domain。案例：**Salient**（贷款服务 voice agent）、**HappyRobot**（货运）、**Reducto**（文档处理），全部一年 0 → 八位数。
- **增长统计**：YC 上一批**平均公司 3 个月 3x**（旧世界只有 top 1% 达 10%/周）；Anthropic economic-index 图显示软件外的巨大 whitespace → "hundreds of AI unicorns waiting"。

## 关键观点

> "老公司是 open loop，误差会累积到脱轨；AI 让公司变成 closed loop。"

> "Shipping code is going to zero. Taste is not."
